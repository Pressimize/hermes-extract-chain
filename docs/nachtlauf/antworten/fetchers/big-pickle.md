1. **Bug** – `fetchers.py:129`/`135` — In Batches (≥2 URLs) geht der Inhalt verloren, wenn TinyFish eine Eingabe-URL anders benennt (z. B. Redirect `http`→`https` oder `www.`). `exact`/`found` sind nach dem Reply-Namen indexing; der Einzel-Fall-Remap (Zeile 129, `len(urls) == 1`) greift nicht, die betroffene URL bekommt `no_result`, obwohl die Reply den Inhalt liefert. Bei ≤5 URLs von Hermes ist das realistisch. Fix: Remap auf Batches ausweiten (z. B. für jede untreffende Eingabe den verbleibenden Reply-Eintrag zuordnen, wenn nur noch einer übrig ist).

2. **Edge Case** — `fetchers.py:129-130` — Der Einzel-URL-Remap schreibt auch Fehler-Einträge mit fremder URL auf die Eingabe um: Eingabe `https://a.example/`, Reply `errors: [{"url": "https://b.example/", "error": "bot_blocked"}]` → `a.example` meldet `bot_blocked`, obwohl nie für diese URL gefetcht wurde. Fix: Remap nur auf `results`-Einträge oder nur bei (normalisiert) gleicher Host/Scheme.

3. **Edge Case** — `fetchers.py:117-128` (Test `test_fetchers.py:139`) — Für eine in `results` *und* `errors` genannte URL gewinnt immer der Fehler, weil der Errors-Loop nach dem Results-Loop läuft — unabhängig von der Reihenfolge in der Reply. Der Testkommentar „the later entry counts" beschreibt aber Reply-Reihenfolge; sendet TinyFish erst Fehler dann Ergebnis, wird der Erfolg verworfen. Fix: Gewinn-Regel explizit festlegen (z. B. Ergebnis gewinnt) und Test/Kommentar angleichen.

4. **Edge Case** — `fetchers.py:107-110`/`134` — Eine 2xx-Reply als JSON-Objekt ohne `results`/`errors` (z. B. `{"status": "ok"}`) wird nicht als `malformed` gewertet, sondern führt pro URL zu `no_result`; der Log-Code (L1) unterscheidet damit nicht zwischen „Antwort unbrauchbar" und „Seite nicht geliefert". Fix: nach dem Parsen prüfen, ob `results` oder `errors` vorhanden sind, sonst `malformed`.

5. **Stil** — `fetchers.py:46` — Der ternäre Ausdruck als `for`-Iterable (`for form in {key, quote(key, safe="")} if key else ()`) ist schwer lesbar; Separate-Zuweisung (`forms = ... if key else ()`) mit anschließendem `for` ist klarer.
