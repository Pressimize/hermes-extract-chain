# Review of 0.3.0 (2026-10-18)

Three reviews of the 0.3.0 branch: one helper checked the plan against the specification, one the result against it requirement by requirement, and two free models (DeepSeek v4.1 Flash and Beam, via the opencode client, without access to the repository) read the code diff with `design.md`. Every point was checked against the code; fixes come with a test. The raw answers are not in the tree.

## Fixed

| What | Test |
|---|---|
| An interrupt between stages did not stop the chain: it went on waiting for Keenable (S8). The chain now stops, does not wait and the provider cancels Keenable's request. | `test_interrupt_between_stages_cancels_the_running_keenable_task` (`tests/test_provider.py`) |
| K9: Keenable's copy after two 404/410 answers was taken even when it was a consent page; now only `ok`, `thin` or `paywall` (V3 kept). | `test_two_live_404_without_copy_is_an_error`, `test_gone_copy_with_paywall_keeps_v3` |
| K9: when Keenable had not answered in the time left, the reasons did not name it. | `test_gone_without_keenable_answer_names_keenable` |
| A1: proxy codes arrive as `x-brd-err-code` / `x-brd-err-msg` as well; they are read, and a quota code there starts the pause. An empty error header is no error. A `status_code` sent as text is read. | `test_brightdata_*` (`tests/test_fetchers.py`) |
| C5: a Keenable consent page or bot check served as the reference and could make a complete live result suspect; only an `ok` or `thin` copy is a reference now. | `test_keenable_consent_page_is_no_reference` |
| The log line could raise in its `finally` block and fail every URL of the call (S6). | `test_unexpected_failure_while_logging_the_reference_does_not_raise` |
| A repeated `keenable` in `EXTRACT_CHAIN_ORDER` did not warn. | `test_repeated_keenable_warns` |
| Documentation: Tavily's request timeout is at most 25 s (stage deadline 30 s minus 5 s); `thin` never appears in the log, a short result shows as `suspect_thin`. | none (documentation) |

## Not taken

| Point | Why not |
|---|---|
| Duplicate input URLs run the chain twice (K5). | `extract()` removes duplicates before the chain and copies the result to every position (S5); `_chain` sees each URL once. |
| A Keenable quota reply is lost when its request is cancelled. | The pause is set right after the reply, without an `await` in between; a request is cancelled only while it waits for the reply, when there is nothing to lose. |
| Warn when `web.extract_timeout` is 0. | 0 means no limit in Hermes; the budget is then 170 s, nothing is wrong. |
| Wait for Keenable at most its deadline instead of the time left. | The Keenable request has its own deadline (25 s from the start of the URL), so waiting for the time left never waits longer. |
| Base Keenable's deadline on the time left when waiting starts. | The request starts with the URL; the budget is the time left at that moment. |
| Log `keenable=exception` when the task raises. | The task catches every exception and returns an error entry; it never ends with an exception. |
| The second fallback branch could hold non-C3 results. | It is reached only when no result without C3 was kept, so every remaining entry is a C3 result. |
| Missing tests for K9's Firecrawl gate, a target 402 without pause, duplicates. | They exist: `test_no_early_end_once_firecrawl_was_asked`, `test_paused_or_skipped_firecrawl_was_not_asked`, `test_no_pause_for_429_or_a_target_402`, `test_order_and_duplicates`. |
| Messages from Bright Data that are present but empty should be kept. | An empty message carries no information; the code stands alone. |
