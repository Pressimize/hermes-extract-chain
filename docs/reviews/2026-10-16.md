# Code review 2026-10-16

> Record of a past review. It covered the TinyFish chain on `main` before v0.2.6, which shipped its fixes; rule IDs are those of `design.md` at tag `v0.2.6`. TinyFish, its pause until 00:05 UTC and its key were removed in 0.3.0. The replay listed as open was run for v0.2.6, the live check was not ([validation.md](../validation.md)). The current rules are in [design.md](../design.md).

Seven free models, run through the opencode client, and Claude reviewed the plugin in four areas: `fetchers`, `chain`, `provider` and the developer scripts. About 210 individual points came back. Every one was checked against the code of `main` and, for claims about Hermes, against the Hermes Agent v0.21.6 source; where possible it was reproduced with a script or test. Five points held up; the rest is listed below so that later reviews do not raise them again.

The raw model answers, prompts and per-model notes are not in the tree. They are preserved under the git tag `review-2026-10-16-raw` (commit `4bb420a`).

## Fixed

Each code fix has a test that failed before the change.

| ID | What | Test |
|---|---|---|
| N01 | The pattern for the visible length (E2) removed everything between a `<` in the text and any later `>`. A 3,270-character article with `x < 10` and a later `->` counted as `empty`; a Python text with `` `a < b` `` and `>>> 1 < 2` counted as `thin`. The complete TinyFish text was discarded and Firecrawl (1 credit) and possibly Keenable were asked. The pattern was also quadratic: 320 kB of `<` without `>` cost 13 s CPU in the event loop, blocking all URLs of the call. A tag now needs a tag name followed by whitespace, `/` or `>`; comments and doctype are matched separately. Code such as `for (i=0; i<n; i++) ... p->next` therefore stays text. | `test_less_than_sign_is_no_tag`, `test_many_less_than_signs_classify_in_linear_time` (`tests/test_chain.py`) |
| N02 | Firecrawl `data` or `metadata` that is no object ended as `Firecrawl: AttributeError` with code `AttributeError`. It is now `malformed`, as for TinyFish and Keenable. The result was an error before as well; only text and log code change. | `test_firecrawl_data_that_is_no_object_is_malformed` (`tests/test_fetchers.py`) |
| N03 | `docs/troubleshooting.md` said that pages with "Access denied" or challenge text are not recognised. Since 0.2.5 they are, below 1,500 visible characters (E7). Text corrected. | none (documentation) |
| N04 | `scripts/replay.py` aborted on a stored error detail that is valid JSON but no object (`402`, `null`), before the table was printed. | `test_replay_error_detail` (`tests/test_scripts.py`) |
| N05 | `scripts/live_check.py` matched L1 log lines by host only. With two URLs of one host in a call, the later line overwrote the earlier one, so a TinyFish answer was checked against the other URL's Keenable line (false alarm "Keenable result without note") or a missing note went unnoticed. URLs of one host are now checked together in `check_call()`. | `test_live_check_two_urls_of_one_host`, `test_live_check_one_url_per_host` (`tests/test_scripts.py`) |

N03 to N05 do not touch the shipped plugin behaviour; N02 changes only the error text and code. N01 changes the class only of texts whose visible length was measured wrongly. Markers, thresholds, notes and stage order are unchanged.

## Rejected

Settled points, grouped by reason. Do not re-propose them without new evidence.

### Deliberate, documented decisions

- **Marker search on the raw text.** Wall and paywall markers, `WHOLE_BELOW` and `WALL_WINDOW` work on raw `content`, not on the visible text (E3, E4). The providers return Markdown (A1 to A3, S4); examples with `<script>` blocks assume raw HTML that none of them delivers.
- **One bot-check marker below 1,500 characters is enough.** A real short article about captchas is a known false positive; it is returned with V11 anyway (E7, D21, D25, section 13). Long bot-check pages count as `ok` (E7).
- **Redirect note (V10, D22).** It appears on every host change (`m.` subdomain) and for a two-letter path segment (`/in/`, `/it/`), but not for a different port or a different non-empty path. The note carries the full final URL including the query; the model is meant to see where it ended up, and Hermes rejects URLs with secrets before any fetch. URLs are absent only from the log line (L1). A note never changes class or stage order.
- **402 pause (K7, D14).** The jump from seconds to 24 h at 00:05 UTC is intended: a 402 after 00:05 means the new daily quota is used up; the five minutes cover clock skew only.
- **Single-URL fallback and batches (A1).** A single-URL request accepts an answer with a different URL (redirect). `errors[]` wins over `results[]` for the same URL, a reply without both is `no_result`, and a redirect inside a batch is `no_result`. A TinyFish code over 40 characters becomes `fetch_failed`; transport codes are CamelCase class names.
- **Policy and blocks (S7, D19).** A block after a redirect replaces the result's metadata, and the exception type appears in the block text. A policy check that raises blocks the URL.
- **Errors without detail (S6).** Only the exception class is reported, not its message, which may contain a URL or page content.
- **Keys (K1).** `TINYFISH_API_KEY` is listed as required, yet the chain continues without it. See "Missing TinyFish key" in `docs/troubleshooting.md`.
- **Keenable reasons (K4).** A Keenable consent wall is not kept as a wall page; only wall and bot-check pages of the live stages are kept, and an earlier bot-check page wins.
- **Interrupts (S8).** `/stop` does not abort running requests; they end at their deadline (A0).
- **Load failures (section 13).** `register()` does not catch an `ImportError` of the base class; without `agent.web_search_provider` the plugin does not load.

### Hypothetical: inputs that neither Hermes nor the providers produce

- Firecrawl `success` or `statusCode` as strings; Firecrawl HTTP 200 without `success` (ends as an error with code `api_200`, correct, and the chain moves on; K7 reacts only to 402).
- Very short API keys that mangle codes when redacted; artificial keys only. (Changed after this review: keys below 8 characters are no longer masked, as in search-chain.)
- Malformed internal dicts: `pdf_pages` not a pair, `content` not a string, an `error` document without `error` key, a falsy `code`, a `KeyError` on a 402 document, a gap in `done`. These dicts only come from `fetchers.py`, which guarantees the types (`zip(..., strict=True)`, `_error`).
- HTML entities and `<script>`/`<style>` contents counted as visible text. The providers return Markdown; the worst case is one extra Firecrawl request on a constructed page.
- `urls` as iterator, non-string URLs, empty or relative URLs, a missing `finalURL`: Hermes passes a list of validated strings (`_validate_extract_urls`), and `provider.extract` deduplicates and never calls the chain with an empty list.
- A block message without the prefix "Blocked by website policy" fooling the keyless rescue. Refuted in Hermes v0.21.6: `tools/website_policy.py` always starts the message with that prefix, and `tools/web_tools_rescue.py` detects blocks by a non-empty `blocked_by_policy` or by the lower-cased text.
- No `tools.interrupt` module: it exists since Hermes 0.21, and S8 is best effort anyway.
- Scripts: JSON answers of `web_extract_tool` that are no string (declared `-> str`), `null` entries, blank or broken lines in stored data (fixed data that already ran, `docs/validation.md`), log lines without host (every `extract-chain ` line has one).

### Factually wrong

- A pause with `left == 0` is treated as over: correct.
- `UnicodeDecodeError` escapes `_json`: it is a subclass of `ValueError`.
- Pause reason or log code can contain keys: the reason is the already redacted one-line text from `fetchers._error`; codes come from a fixed set; the Keenable JSON error path redacts too.
- `record.getMessage()` falsifies the prefix filter in `live_check.py`: it returns exactly the formatted line. Keenable `ok` with empty content: `ok` does not mean empty and carries V4. Multi-line errors in notes: provider errors are one line and cut (A4).
- `httpx.AsyncClient` without `timeout=` applies 5 s to every stage: `fetchers._request` passes `timeout=deadline` per request (A0).
- The provider violates the base-class contract (no `super().__init__()`, `name` as property): Hermes v0.21.6 `agent/provider_base.py` defines `name` and `display_name` as properties itself and has no `__init__`.
- `_left(3600)` printing "60 min" is wrong: it is correct; only the "under an hour" boundary is taste.

### Performance without measurable effect

- Redaction and whitespace folding over megabyte error pages: 4 MB take 0.3 to 0.7 s, linear, and are tested (`test_megabyte_error_page_gives_a_short_error`). Truncating first could split a key at the cut.
- `_visible` computed several times per URL: linear after N01; D18 measures 13 ms per 100,000 characters.
- `deepcopy` per entry (S5 requires separate objects per position) and `_paused` growing with every new key.
- Scripts: quadratic rate window, sleep after the last group, `raw` in `results.jsonl` (intended; it is the output as the model sees it). The scripts handle at most about 100 URLs.

### Developer scripts: intended or harmless

- `live_check.py` has no `try` around `asyncio.run` and keeps comparing after an "order/count" problem: the problem is reported and every line is flushed; Hermes catches tool errors itself.
- `KEENABLE_NOTE` is copied, not imported: the script runs with `-I` in Hermes' Python on purpose. V4 is always the first note line.
- `results.jsonl` is opened in append mode so runs accumulate; `out/` is in `.gitignore`, the docstring warns.
- `ROOT` is relative without `HERMES_ROOT`/`LOCALAPPDATA`, `assert` instead of `SystemExit`, root-level INFO: documented, and the failure comes at import. Run with `-I`, not `-O`.
- All `*_API_KEY` variables are removed from the environment: intended, keys come from the profile only.
- The prototype gets raw data and synchronous lambdas, the plugin normalised data; `exec_module` loads arbitrary code: the prototype is the author's own code.

### Style and test gaps without a defect

Names (`short`, `page`, `check`), literals for provider names, a ternary as iterable, repeated two-liners, magic slices in the scripts, `if not 0 < left <= DAY`, a marker-uniqueness test that omits `CHALLENGE` and does not compare regex against regex. No misbehaviour shown; changes would be taste.

## Method

Each model was called separately with the original files of `main` attached. In the first pass the models ran as an opencode agent with shell access, and one of them read the answers of two others via `cat` (confirmed in the opencode session database). That model's `chain` answer does not count as independent. Runs that might have seen foreign answers or fixes, and runs without an answer, were repeated in a fresh single-branch clone of `main` with no remote, no answers and no fixes; each answer was copied out at once. The number of models that mention a point is no measure of its weight; N01, the most useful finding, was reported by only two of them, independently.
